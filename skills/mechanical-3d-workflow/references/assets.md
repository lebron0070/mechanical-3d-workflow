# 资产建模合同

## 建模路线

先确认对象类型、版本、尺寸依据与可观察角度，再选择方法。Blender参数化几何适合重复机械件、对称结构、叶片阵列和装配；有精确尺寸与制造要求时考虑CAD/B-rep，复杂外观则需要连续曲面或雕刻。不要把程序化盒体数量当精细程度。

按轮廓→总成关系→曲面/厚度/倒角→内部结构→小细节递进。外壳分片从同一曲面采样，避免拼接处各自起伏。材质区分涂装、裸金属、橡胶、玻璃等；配色取自对象或用户要求，不继承其他案例。

## 节点分层

```text
产品根节点（整体放置）
└─ 总成展示节点（装配/拆解/变形姿态）
   ├─ 固定件
   └─ 关节或转轴节点（局部运行）
      └─ 运动网格或下级机构
```

父节点关系必须无环。总成选择可以覆盖多个网格，但材质合并不能跨越运动边界。轮转动时卡钳保持在支架上；风扇转子旋转时机匣/定子不旋转。导出后检查节点层级仍存在。

## 最小数据示例

以下是米制、Y向上、四元数 `[x,y,z,w]` 的示例，不是所有项目必须采用的字段标准。整个项目只选一种坐标约定，与导出器转换保持一致。

```json
{
  "id": "fan-module",
  "label": "风扇总成",
  "parentId": null,
  "assembledPose": {"position": [0, 0, 0], "quaternion": [0, 0, 0, 1]},
  "explodeOffset": [0, 0, 2],
  "description": "前部气流压升模块；具体结构以所选型号为准",
  "motion": {
    "nodeId": "fan-rotor",
    "type": "rotation",
    "axis": [0, 0, 1],
    "pivot": [0, 0, 0],
    "speedUnit": "rpm"
  }
}
```

单形态不存虚构的robot/car端点。多形态时另加按名称组织的 `poses` 和转换边；明确选择哪条转换、方向和进度。关节限位、运动关系、说明来源按对象补充，不猜制造参数。

先用一个不对称测试件验证朝向、单位、原点及局部/世界转换。每个转轴原点放在真实支点，保持组件几何和动画使用同一坐标；不要先导出转换、再在网页重复转换。

## 导出与验证

保留可编辑源文件和导出文件；manifest记录版本、组件ID、节点归属、计数与验证状态。使用实际导出顶点重新求包围盒，不只相信预填数据。测试法线、材质、动画节点与外部纹理是否完整。

性能预算依据目标设备实测：draw call、三角面、纹理、像素比、阴影/AO、CPU姿态更新与录制开销。实例化适合重复不独立变形的部件，但仍须实现实例ID到总成的选取映射。

若要求3D打印：另外确认尺寸/单位、封闭流形、薄壁、孔轴间隙、公差、自交、分件/支撑及切片；关键机构试印。网页效果、GLB与静态包围盒均不能证明可制造。
